# Local allow-list composition and reviewed root commits

C6 provides local composition primitives. A composed tree is a **candidate**, not
publication admission, a completed source freeze, a release or a remotely staged
repository. The implementation exercises synthetic fixtures only: no fourteen
real targets have been materialized or qualified by these tests.

## Inputs and independent authority

`composeTarget(input, trustedPolicy, outputRun)` takes the complete C3 source file
inventory, entrypoints, edges and dispositions; C4 license evidence; exact local
source roots and commits; generation descriptions; and boundary evidence.
`trustedPolicy.inputDigest` binds the entire input with `digestEvidence`, including
source roots. The trusted policy is supplied independently by the reviewer and
contains the C4 policy plus approved generation/boundary record digests. A submitted
record cannot approve itself by repeating its hash. Review evidence is opaque;
raw identities, grants and compliance archives are never collected automatically.

The composer calls `buildPathManifest` and `auditLicenses`, refusing any rejected
path set or rights result. It then enumerates every tracked Git path at each exact
commit, refuses nonregular files including symlinks/gitlinks, reads raw blob bytes
and recomputes SHA-256. The inventory must cover the complete tree, including
paths marked for deletion. A partial submitted inventory cannot hide an extra
file. Worktree edits are irrelevant; no source worktree, ref or index is changed.
Replacement objects and lazy fetching are disabled. Git runs with an empty
environment plus explicit noninteractive/read-only settings and a fixed system
PATH; inherited Git directory/index/config overrides are not honored.

C1's shared binary runner supplies irreversible 30-second deadlines and a 16 MiB
per-command output cap. Composition rejects more than 256 MiB of total source
bytes or resulting target bytes. These are explicit implementation bounds, not
silent truncation. Source roots and the existing output parent must be canonical
absolute paths without symlink aliases; use `realpath` when preparing local inputs.
No subprocess runs source code, dependency scripts or submitted shell commands.
Output under a source worktree or its shared Git metadata is refused. Source
roots must identify the Git worktree top level, not a subdirectory.

## Materialization and generated bytes

Only allow-listed target paths are copied, with byte-identical content and Git
executable/nonexecutable mode. C3 enforces traversal, case-normalized collisions,
file/directory collisions, sensitivity and complete dispositions. C6 additionally
binds every retained file's source commit/digest/destination to the rights record
and verifies required notices against actual composed target bytes.

A generated file keeps its old `sourceDigest` in the source manifest. Its output
gets a separate verified `targetDigest`. A reviewed generation record binds the
file ID, canonical source ID, recipe ID, review evidence and expected target
SHA-256. Canonical generation chains resolve recursively. The current closed
recipe registry contains `identity.v1` (exact reviewed canonical bytes) and
`canonical-json.v1` (UTF-8 JSON, recursively sorted keys, two-space formatting and
terminal newline). The recipe executes twice and both results must match the
reviewed digest. Unknown recipes, absent canonical source or mismatched bytes
reject. Additional product-specific generators require a reviewed implementation
and tests in this registry; arbitrary code in input is never a generator.
Reviewed README shells, REUSE files, lockfiles, manifests, docs and examples can
be copied unchanged or produced through these explicit recipes. Their existence
alone is not proof of installation, package consumption or product tests.

An exclusive new mode-0700 run directory is created only after validation. Its
private `.staging` tree is filled, then renamed atomically to `<run>/<slug>`.
Existing run directories are refused; no existing target is replaced. On an I/O
failure the private run/staging directory can remain for inspection; it is not a
successful target and is not automatically deleted. The returned tree digest
covers sorted target paths, SHA-256 byte digests and executable modes; it excludes
filesystem timestamps and Git metadata. Run twice into distinct new directories
to establish reproducibility.

## Layout boundaries

Missions Auth and Build Brief runtime code must land in the existing
`apps/missions/src/{app,authz,domain,persistence,server,shared,ui}` domains. Extra
feature hierarchies and separately packaged single-consumer runtime code reject.
Contracts keep editable contract files under `contracts/`; generated files live
under `generated/typescript/` or `generated/rust/`. Packaging verification remains
part of S/R qualification, not inferred from path names.

Sessions data-rights runtime code stays in `apps/sessions/src/rgpd`; an alternate
internal boundary requires separately trusted consumer/reachability evidence.
The same explicit boundary proof is required for retained ecosystem-engine and
envelope runtime code. Supporting notices/docs/tests/assets are still governed
by C3 reachability/support and C4 rights; they need not impersonate runtime code
paths. These rules validate reviewed mappings and do not invent integrations.

## Signed root boundary

`createSignedRootCommit(target, signingKey, preparation, trustedRootPolicy)` is
separate from composition. Preparation must include opaque reviewed surface (S)
and release (R) implementation evidence, source-freeze evidence, a second composed
target and the reviewed license path/digest set. The independently trusted policy
binds that complete preparation, the target tree and composition evidence, the
expected SSH public key and a GitHub noreply author. Missing S/R evidence refuses
before initializing Git. Reviewers must substantiate these evidence references;
a hash-shaped string is not independently discovered proof.

Both candidate directories are reread and must reproduce the same approved tree.
No preexisting `.git`, symlink, extra file, changed bytes or unsupported file kind
is accepted. Git initializes without templates or hooks and with isolated config.
After staging, the exact Git tree is rehashed: Git attribute normalization cannot
silently change reviewed bytes. `commit-tree -S` creates a parentless SSH-signed
commit, verified offline against the separately pinned public key before the new
main ref is created. The key is explicit and must be a private regular file; the
tool never creates or chooses production signing keys. Failed signing/verification
may leave private Git metadata for inspection, without a successful root result.

Tests generate ephemeral SSH keys for synthetic fixtures and remove only their
own temporary directories. No fixture signature substitutes for the owner's
signature. The root commit does not embed its own future SHA; publication receipts
and final artifact binding remain separate external evidence. Conditional targets
are only local candidates here; C5 and cutover gates still govern public names,
final private staging and publication. Registry installation, complete product
qualification, secret/PII audits and actual S/R completion are not executed or
inferred by these file-composition primitives.

## Reproduction

```sh
bun test tools/migration/compose-target.test.ts tools/migration/target-layouts.test.ts tools/migration/root-commit.test.ts
bun tools/migration/compose-target.ts --input reviewed-input.json --policy approved-policy.json --policy-sha256 APPROVED_RAW_POLICY_SHA256 --output /private/new-run
```

The CLI bounds JSON reads, pins the raw policy-file bytes from the independent
review channel and emits only candidate slug and opaque digests. Diagnostics are
fixed codes; host paths, raw source bytes, Git stderr and identities are omitted.
The API's returned directory and path manifest are private orchestration data.
