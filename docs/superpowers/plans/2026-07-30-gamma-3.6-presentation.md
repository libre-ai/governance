# γ 3.6 Présentation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every repository of the constellation carries its `project.v1.yaml` state card and a README whose status section is generated from it; the state authority migrates from the central inventory into the cards; org README, website homepage with the fleet-status table, dated comparisons and GitHub descriptions complete the public presentation (design §6, ADR-0020).

**Architecture:** The 3.2 machinery (`ecosystem/project-cards.ts` in governance: `validateCard`, `aggregateProgress`, `renderStatusSection`, `checkStatusSection`, sentinels) is consumed cross-repo, never duplicated. Cards are generated locally from the hub inventory's state fields (double presence), pushed per repo, proven green; only then does the topological index v2 drop the migrated state. A governance fleet gate verifies README↔card coherence across all repos; the website consumes a governance-generated fleet-status projection.

**Tech Stack:** Bun + strict TypeScript, YAML cards (schema `libre-ai.project.v1`), GitHub API via `gh`, reusable fleet workflows pinned by SHA.

## Global Constraints

- Nothing merges or is pronounced done without green proof (hub CLAUDE.md; design §7.1).
- No manual percentage anywhere; planned capability never presented as available (design §7.5).
- Free text follows the mission formula: « Pour [utilisateur], qui rencontre [problème], ce projet permet de [résultat observable], en produisant [sorties], sans dépendre de [contrainte] » — accessible vocabulary, no technology on the first screen (design §6.5).
- One state authority per project: state fields (`hypothesis`, `evidence_required`, `promotion_criteria`, `kill_predicates`, `exposure`, `benchmark`) leave the inventory only after their card is green at destination (design §6.2 — the path-migration hard rule applied to data).
- Generated sections live between `<!-- libre-ai:project-status:begin/end -->` sentinels and are never hand-edited (design §6.4).
- LEXICON §1.1: seven code-bearing products + the missions layer-2 app; `carriere` is the ratified eighth product, spec-less; never « 8 produits » unqualified.
- Commits signed (`git commit -s`, author Constantin Jais <cjais@pm.me>), no Co-Authored-By, squash+DCO on hub merges.
- K4 role-separated review on immutable commits for hub doctrine/evidence PRs and the governance gate PR.
- Repository names only from the LEXICON; `bun run check:names` green everywhere.
- Machine-local absolute paths never enter tracked files.
